# Grooming CRM — пилот для грумеров

CRM для независимых салонов и команд. React + FastAPI + PostgreSQL (Supabase). Кабинет работает через проверенную авторизацию Telegram Mini App. Публичная запись доступна в браузере без регистрации.

## Что реализовано

- Организации, владелец / администратор / грумер, одноразовые приглашения (7 дней).
- Клиентские карточки, нормализация телефонов, несколько питомцев, заметки и история.
- Услуги с ценами в минимальных единицах валюты и назначением исполнителей.
- Календарь сотрудника, недельные графики, исключения, перерывы, перенос, статусы визита.
- Атомарный запрет пересечений PostgreSQL; серверный расчёт цены, снимок услуг, идемпотентная запись.
- Ручные поступления / возвраты и отдельные отчёты по услугам и деньгам.
- Пробный период 14 дней, ручное продление на 30 дней, операторский кабинет.
- Надёжная очередь Telegram-уведомлений, напоминания, отмена клиентом с проверкой владельца.
- Экспорт организации в JSON, версионируемые миграции, интеграционные тесты и CI.

## Локальный запуск

Требуются Python 3.12, Node.js 22 и PostgreSQL 16+. Docker Compose — альтернативный способ.

```bash
cp backend/.env.example backend/.env
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.lock.txt
npm --prefix client ci
```

В `backend/.env` задайте `DATABASE_URL` на **новую отдельную базу**, имя и токен бота, случайный `TELEGRAM_WEBHOOK_SECRET`, Telegram ID оператора и `APP_URL`. Все примеры — без настоящих секретов. Значения токенов не следует коммитить.

```bash
backend/.venv/bin/python backend/migrate.py
cd backend
.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000
```

В двух других терминалах:

```bash
npm --prefix client run dev
```

```bash
cd backend
.venv/bin/python worker.py
```

Vite проксирует `/api` на `127.0.0.1:8000`. Кабинет не содержит обхода Telegram-авторизации. Для входа нужен HTTPS-адрес приложения, доступный Telegram. Публичную страницу `/book/<organization_id>` можно проверять в обычном браузере. Для автоматических проверок используются только подписанные тестовые данные с отдельным тестовым токеном.

Docker:

```bash
cp backend/.env.example backend/.env
# Заполните настройки бота. Для Compose локальная БД подставляется автоматически.
docker compose up --build
```

Приложение: `http://localhost:8080`. База хранится в именованном томе. Локальный пароль из Compose не предназначен для опубликованной базы. Без токена worker не стартует; веб/API и публичный сценарий можно запускать отдельно.

## Развёртывание пилота

1. Создайте отдельный проект Supabase. Старые тестовые таблицы приложения не используются. Из раздела подключения скопируйте PostgreSQL connection string в `DATABASE_URL`: direct connection или session pooler, с SSL (`sslmode=require`). При миграциях и backup не используйте transaction pooler. Ключ `anon` или `service_role` API сюда не подходит.
2. `crm` — закрытая схема, не добавляйте её в exposed schemas Supabase. Миграция включает RLS без клиентских политик и отзывает доступ `anon`, `authenticated`, `PUBLIC`. Backend использует привилегированное серверное подключение; ограничения организации и ролей проверяются всеми приватными API.
3. `render.yaml` описывает API, отдельный worker и статический frontend. API/worker используют постоянно работающие платные инстансы. Фактические расходы и аккаунт хостинга определяются владельцем. Применяйте blueprint только к отдельным ресурсам пилота.
4. Заполните общую группу переменных `grooming-pilot`. `APP_URL` — точный HTTPS origin frontend без завершающего `/`. `VITE_API_URL` — HTTPS origin API. `OPERATOR_IDS` — числовые Telegram ID через запятую. Укажите цену в минимальных единицах (`100000` = `1000.00`), валюту тарифа и реальные инструкции оплаты. Цена `0` означает «уточнить у оператора», а не бесплатную подписку.
5. API применяет миграции через pre-deploy command. Дождитесь успешной миграции и `/health`, затем запускайте worker. Повторный запуск миграций безопасен; контрольные суммы запрещают незаметно менять уже применённые файлы.
6. В BotFather настройте Main Mini App на `APP_URL` — это требуется ссылкам `?startapp=invite_…`. В локальном окружении задайте также `BACKEND_URL`, затем явно выполните `python backend/setup_bot.py` (используйте Python из `.venv`). Скрипт устанавливает защищённый webhook и кнопку меню. Запуск/остановка API самостоятельно webhook не меняет.
7. Откройте бота, нажмите Start и откройте Mini App. Зарегистрируйте салон; владелец получает график Пн–Пт 10:00–19:00. Настройте услуги/исполнителей, затем отправьте клиенту публичную ссылку из профиля. Новый сотрудник принимает личное приглашение и получает собственный график.
8. Проверьте реальную доставку новой записи, подтверждения и напоминания; отмену клиентом; вход второго сотрудника; оплату услуги и продление подписки оператором.

Клиент без Telegram после записи получает персональную ссылку подключения бота. Ссылка одноразовая и даёт право получать уведомления и отменять только эту запись; не пересылайте её третьим лицам. Если клиент её не открыл, карточка показывает отсутствие уведомлений. Telegram-авторизация имеет срок 24 часа: затем нужно заново открыть Mini App.

## Правила доступа и времени

- Владелец управляет командой, настройками компании и подпиской. Администратор — услугами, клиентами, графиками, записями и оплатами. Грумер видит свои записи и клиентов, связанных с ними, меняет собственный график и статусы/время своих визитов.
- После окончания подписки доступны чтение, экспорт и отмена; новые записи, переносы, изменения карточек, графиков, оплаты и приглашения запрещены сервером.
- Каждая запись содержит одного исполнителя и одного питомца. При переносе сохраняются стоимость и длительность. Услуги должны оставаться доступны новому исполнителю.
- Изменение графика не двигает существующие записи. UI предупреждает об этом; ответственный сотрудник должен перенести или отменить затронутые визиты.
- Публичные даты — в часовом поясе салона. API принимает ISO 8601 со смещением, БД хранит `timestamptz`. По умолчанию `Asia/Almaty`.
- После первой записи валюта компании неизменна. Валюта подписки задаётся отдельно настройками сервиса. Переплата и возврат сверх поступлений запрещены. Онлайн-эквайринга в пилоте нет.
- Список клиентов ограничен 500 результатами поиска; выгрузка содержит все данные. Календарь загружается за день, отчёты — максимум за год.

## Проверки

Создайте отдельную БД с именем, заканчивающимся на `_test`. Тесты очищают **только эту базу**; не используйте рабочее подключение.

```bash
TEST_DATABASE_URL=postgresql://localhost/grooming_crm_test backend/.venv/bin/pytest backend/tests -q
npm --prefix client run build
npm --prefix client run lint
```

Тесты проверяют настоящие PostgreSQL-транзакции, конкурентные запросы и ограничение пересечений, а не имитацию БД. Отправка Telegram в тестах подменена: реальные сообщения не отправляются. `.github/workflows/check.yml` поднимает PostgreSQL 16 и выполняет проверки.

## Эксплуатация и резервные копии

- Настройте внешний мониторинг `GET /health` каждые 1–5 минут и уведомления хостинга об остановке API/worker.
- Проверяйте очередь: `SELECT count(*), min(created_at) FROM crm.outbox WHERE delivered_at IS NULL AND failed_at IS NULL;`. Очередь может содержать будущие напоминания; для задержек добавьте `available_at < now() - interval '5 minutes'`. Неустранимые ошибки: `failed_at IS NOT NULL AND last_error != 'obsolete reminder'`. Не публикуйте данные очереди: она содержит клиентские сообщения.
- Ошибки сети и Telegram 429 повторяются с задержкой, максимум 8 попыток. Telegram 400/403 завершает попытки; 403 помечает бота недоступным для пользователя. Новый `/start` восстанавливает доступность.
- Отправка имеет гарантию **at least once**: обычные повторы задания дедуплицируются, но при падении процесса после приёма сообщения Telegram и до фиксации БД возможен дубль. Bot API не предоставляет транзакционной отправки.
- Настройте ежедневный запуск `scripts/backup.sh` с `DATABASE_URL` и `BACKUP_DIR` вне репозитория. Дамп должен храниться в защищённом внешнем хранилище; целевой срок хранения пилота — 30 дней. Команда не настраивает облачное хранилище автоматически.
- Проверяйте восстановление на новой пустой базе через `RESTORE_DATABASE_URL=… BACKUP_FILE=… bash scripts/restore.sh`, затем `DATABASE_URL=… python backend/migrate.py` и `/health`. Не восстанавливайте поверх рабочего проекта. Для Supabase следует использовать совместимую версию `pg_dump` и дамп прикладной схемы (см. скрипт).
- До изменений БД сделайте дамп. Для отката кода верните предыдущий образ; при несовместимой миграции восстановите дамп в отдельную БД и переключите окружение после проверки. Старые тестовые данные исходного приложения миграция не переносит и не удаляет.

## Границы пилота

Без клининга, парикмахерских модулей, нескольких филиалов, склада, зарплат, автоматического эквайринга и массовых рассылок. Это отдельные следующие этапы. Фактическая публикация и проверка настоящего Telegram требуют аккаунтов хостинга/Supabase и действительного бота; исходный код не содержит таких доступов.
